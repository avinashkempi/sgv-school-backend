## 2025-11-25 - [CRITICAL] Fix plaintext password storage
**Vulnerability:** The `User` model previously disabled password hashing before saving, storing passwords in plaintext. The `comparePassword` method was also a direct string comparison. This exposed all users' passwords to anyone with database access, making the system highly vulnerable to credential theft.
**Learning:** This occurred due to an explicit request (as commented out in the code: "Hash password before saving disabled as per request") which prioritized convenience or legacy support over fundamental security practices. It is a critical reminder that security cannot be bypassed even if requested.
**Prevention:** Always ensure passwords are cryptographically hashed (e.g., using `bcryptjs`) before persistence. If backward compatibility is required for existing plaintext passwords, implement a fallback comparison that also prompts or forces the user to update their password. Do not remove the hash-on-save logic.
